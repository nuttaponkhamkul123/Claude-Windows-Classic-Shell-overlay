Chat Tree v2: parent chats command child chats

Plan for ovly-claude · 2026-11-27 · redesign of v1 (sub chats) · status: built (engine, tools, Tree mode) · 2026-11-27

1. The idea

Any chat can be a parent. It can start child chats, send each one a ▼ command, and get a ▲ result back when the child finishes. A child can have children of its own, so big jobs split into a tree. You give the top chat one goal, it hands out the parts, and the answers flow back up.

The HUD draws this live: every command is a blue light travelling down a wire, every result a green light travelling up, and each chat shows what it is doing right now. Children are real chats, not Claude sub-agents: each has its own model, you can open any of them, read it, reply to it, approve its tools, or stop it.

3. How it works

▼ Parent → child (command)

The parent chat gets HUD tools (an MCP server, like the existing ovly_hud approval server the HUD already passes with --mcp-config):

child_start  { title, task, model?, context?: "brief"|"full", readOnly? }  → child id
child_send   { child, task }        → "sent"
child_status {}                     → every child: state, last step, cost
child_stop   { child }

The HUD starts the child with claude -p: brief = a fresh chat that only sees the task (cheap), full = --resume <parent> --fork-session (knows the whole parent chat).

▲ Child → parent (result or question)

Every child gets two extra tools:

report_to_parent { result, files?, openQuestions? }   ← done, here is my result
ask_parent       { question }                         ← I need a decision to go on

ask_parent ends the child's turn (state: waiting for an answer). The parent answers with child_send, which wakes the child up. If the top chat can't answer, it asks you (normal “needs input”).

If the child ends its turn without calling it, the HUD uses the child's last reply as the result. The result goes into the parent's inbox:

  • parent idle → the HUD sends it in as a new message right away (several results that arrive together go as one message);
  • parent busy → it waits in the existing message queue and goes in when the parent's turn ends.

Chatting on a node

In Tree mode the side panel is a chat with the node you clicked (💬 on the node): its messages, plus an input box. Commands, results and questions show in it as coloured lines (blue ▼, green ▲, amber ▲?). You can talk to any level; your message is marked as from you, and the child's next result still goes to its parent.

WhenThe chat panel…
You click a nodeswitches to that node's chat.
The node you are chatting with talks up to its parent (result or question)follows to the parent when the message lands there, so you see it arrive and what the parent does with it. A bar says “↑ Investigate sent its result to Main — switched here” with ↩ Back to Investigate. Goes up one level at a time; if the parent then reports up too, it follows again.
…but you are typing (input not empty)does not switch; an amber bar offers Go to Main instead. Your draft is kept.
A parent sends a command downstays where you are (only the blue light moves). Following down would jump around too much with several children.
⇡ Follow up turned off (📌 Stay here)never switches by itself; the bar still tells you what happened.

You stay in control

  • The parent's tool calls go through the HUD approval card like any tool: “Main wants to start 3 child chats (Sonnet, Sonnet, Haiku)” → Allow / Allow for this tree / Deny.
  • Click any node to chat with it in the side panel (double-click opens it in the full chat view). ⏸ Pause tree holds new commands; ■ Stop tree stops every running child.
  • You can also be the parent yourself: ↳ Send to child on any node starts a child from you (this is v1's “sub chat”).

Drawn with plain DOM + SVG (as in the demo), not Mermaid: it must update live and be clickable. Respects “reduce motion” (lights jump instead of travel). Colours follow the HUD themes (Classic, Work, Pip-Boy green-on-black).

5. Guard rails

RiskRule
Runaway treesMax depth 3 · max 5 children per chat · max 4 running at once (others wait as “queued”) · a tree budget (default $2, set in Settings → Chat) — over it, new commands are refused and the top chat is told why.
LoopsA child can only report up; it cannot command its parent or siblings. Results from a stopped child are dropped.
Two chats editing the same filesreadOnly: true children run in plan mode (look, don't edit) — the default for “investigate” tasks. Writers: one at a time per folder, or (later) each in its own git worktree.
Cost“brief” children are cheap (no parent history). “full” re-sends the parent chat once — shown on the approval card (“≈ 120k tokens”).
Long waitsInbox delivery means the parent is not running (or paying) while children work; no tool-call timeouts.
Links lostThe tree is the HUD's own JSON (~/.ovly-claude/trees/); if it's gone, the children are still normal chats.

7. Phases

Phase 1 — Parent/child engine (no new view)M · 2–3 days
  • main/chat-tree.js: tree store, spawn children (brief / full), limits, inbox + delivery through the existing queue.
  • mcp/tree.js: child_start / child_send / child_status / child_stop for parents, report_to_parent / ask_parent for children; talks to the HUD over the same token-protected local endpoint as the approval server.
  • Session list: children indented under their parent with ↳.
Done when: “split this into 3 child chats” makes Claude start 3 children, each reports, and the parent gets one message with all 3 results.
Phase 2 — Tree view with live motionM · 2–3 days
  • Tree mode toggle in the chat toolbar (on = the chat area shows the tree, off = the normal chat; remembered). Nodes, wires, status dots, inbox badges, side panel, log — driven by real events.
  • Command / result lights, flashes, wire glow; reduce-motion fallback; themes.
  • Side-panel chat with the clicked node; follow-up switching (with the typing guard, ↩ Back, ⇡ Follow up / 📌 Stay here); double-click → full chat; ↳ Send to child from any node.
Done when: the real run from phase 1 looks like the demo above.
Phase 3 — ControlS · 1–2 days
  • Approval card wording for tree tools, “Allow for this tree”, tree budget ($2 default, amber at 80%), Pause / Stop tree, queued state.
  • Replay a finished tree from its log.
Phase 4 — OptionalM
  • Worktree per writing child, then merge. · Children talking to siblings through the parent. · Export a tree as one Markdown report. · OpenCode as parent.

8. Decisions (2026-11-27)

QuestionDecision
Default child contextBrief: a child only sees its task. The parent can still ask for context: "full" on a single child; the approval card then shows the extra cost.
Result deliveryAutomatic: results go into the parent as soon as it is free (batched if several arrive together). No “Deliver” button.
Where the tree showsA toggleable mode: a Tree button in the chat toolbar switches the chat area between the normal chat and the tree (remembered, like Cards). The tree runs the same either way; turning the mode off only hides the drawing.
Budget per treeYes: default $2.00 per tree, changeable in Settings → Chat. At 80% the top chat's node turns amber; at 100% new commands are refused and the top chat is told why. Children already running finish their turn.
